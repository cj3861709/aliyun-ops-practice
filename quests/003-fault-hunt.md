# 任务 003：心跳服务异常

**难度**: ⭐⭐⭐☆☆
**类型**: 故障排查（不提供故障类型）

---

## 背景

`quest02` 是一个心跳服务：**每分钟**向 `/var/log/quest02.log`
追加一行带时间戳的记录。它已经稳定运行了两天多。

今天收到一条反馈：

> **"这个服务好像有问题了。"**

**没有更多信息。** 你需要自己判断"有没有问题""问题在哪"，然后修复。

---

## 你的任务

- [ ] 判断服务是否真的有问题（给出依据）
- [ ] 找到根因（用证据，不是猜）
- [ ] 修复它
- [ ] 验证修复真的生效（不是只看命令有没有报错）
- [ ] 写手记 003

---

## 检查器

```bash
/root/ops-lab/quests/check-003.sh
```

**检查器只验证最终状态，不告诉你问题在哪。**
它会等你 70 秒来确认日志是否真的在增长。

---

## 排查方法提示（不是答案）

**第一步：确认现象。** 不要急着改东西。

先回答："有问题"具体表现在哪里？

**可以观察的对象：**

| 观察对象 | 命令 |
|---|---|
| 服务状态 | `systemctl status quest02` |
| 服务自启 | `systemctl is-enabled quest02` |
| 服务的 journal 日志 | `journalctl -u quest02 -n 30 --no-pager` |
| 应用日志内容 | `tail -20 /var/log/quest02.log` |
| **日志文件的修改时间** | `ls -la /var/log/quest02.log` |
| 日志文件属主 | `stat -c '%A %U:%G' /var/log/quest02.log` |
| 服务进程身份 | `ps -o user,pid,cmd -p $(systemctl show quest02 -p MainPID --value)` |
| **文件是否在增长** | 隔 60 秒 `wc -l` 对比 |
| 日志轮转配置 | `cat /etc/logrotate.d/quest02` |
| 轮转产生的文件 | `ls -la /var/log/quest02.log*` |

---

## 核心问题

**`systemctl is-active` 返回 active，能否说明服务在正常工作？**

如果不能，那要用什么指标才能发现"服务已经坏了"？
